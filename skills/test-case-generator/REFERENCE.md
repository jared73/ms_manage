## 测试工具与约定

### API 测试工具（建议）

| 工具 | 用途 | 说明 |
|------|------|------|
| Postman / Newman | API 接口测试 | 导入 API_SPEC.md 中的接口定义 |
| curl | 快速验证 | 命令行 HTTP 请求 |
| JUnit + MockMvc | 后端单元测试 | Spring Boot Test |

### E2E 测试工具（建议）

| 工具 | 用途 | 说明 |
|------|------|------|
| 手动测试 | 验收测试 | 对照 e2e-test.md 逐步操作 |
| Playwright | 自动化 E2E | 后续可引入 |

## 测试数据准备

### 测试账号

| 角色 | 用户名 | 密码 | 用途 |
|------|--------|------|------|
| 管理员 | admin | admin123 | 全权限测试 |
| 操作员 | operator | operator123 | 权限限制测试 |

**注意**：生产环境必须修改默认密码。

### 测试数据隔离

- 测试数据使用明确的前缀标识（如"测试-"）
- 测试完成后清理测试数据
- 不在测试中删除非测试数据

## 错误码速查

| 错误码 | 消息 | 触发条件 |
|--------|------|---------|
| 200 | success | 成功 |
| 400 | 参数校验失败 | @Valid 校验不通过 |
| 401 | 未授权/Token无效 | JWT 缺失或过期 |
| 403 | 权限不足 | 角色权限不够 |
| 404 | {资源}不存在 | ID 不存在 |
| 409 | 名称已存在 | 重复创建 |

---

## 测试场景分类标准

| 分类 | ID 前缀 | 来源 | 最少数量 |
|------|---------|------|---------|
| 正向测试 | TC-API-0xx | AC-ID（验收标准） | 每个 AC 至少 1 条 |
| 异常测试 | TC-API-01x | EC-ID（异常场景） | 每个 EC 至少 1 条 |
| 安全校验 | TC-API-02x | security.rules.md | 至少 2 条（401+403） |
| 参数校验 | TC-API-03x | DTO @Valid 注解 | 每个必填字段至少 1 条 |
| E2E 流程 | TC-E2E-0xx | US-ID（用户故事） | 每个核心流程至少 1 条 |

## Mock 数据与 Given 数据一致性

Mock 数据（fixtures/mock-data.json）中的值必须与 AC 中 Given 的数据值完全一致：

```
AC-001 Given: "用户已登录，且账户余额 > 100 元"
→ mock-data.json: { "balance": 150 }
→ 不能写 { "balance": 999999 } （虽然也 > 100，但不与 AC 对应）
```
