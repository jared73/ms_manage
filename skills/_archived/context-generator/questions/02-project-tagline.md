# 质问 2/6：项目一句话定位

## 收集证据

```bash
# 2.1 从 README 提取
echo "=== README 中的项目描述 ==="
if [ -f "README.md" ]; then
  # 取前 30 行
  head -30 README.md
fi

# 2.2 找项目简介
echo "=== 项目简介 ==="
grep -A 3 -i "简介\|intro\|overview\|what is\|项目介绍" README.md 2>/dev/null | head -10

# 2.3 从 pom.xml 看
echo "=== pom.xml name/description ==="
grep -A 1 "<name>\|<description>" pom.xml 2>/dev/null | head -10
```

## 质问内容

```markdown
## 质问 2/6：项目一句话定位

**现有证据**：
- README.md 提到：[如"圆通订单中心" + "处理订单"]
- pom.xml 描述：[如有]
- 推断：[基于证据的猜测]

**请用一句话描述项目是做什么的**（30 字以内）：

A. 处理订单全生命周期（创建/修改/查询/取消）  ← 推荐（如材料支持）
B. 对接外部平台，承接拼多多/微信/支付宝订单
C. 向抖音/京东/淘宝等渠道推送订单轨迹
D. 其他：______（请自行输入）

**说明**：
- 这句话会出现在 project-overview.md 顶部
- 也会被其他 skill 引用作为"项目是什么"的简要回答
- 越具体越好，避免"高效"、"稳定"等空话
```

## 边界情况

### 情况 1：项目是多产品线综合
```markdown
💡 多产品线项目可以这样写：
"圆通订单处理综合平台，包含订单中心、物流接入、推送三大模块"
```

### 情况 2：项目是单体应用
```markdown
💡 单体应用可以这样写：
"圆通订单管理系统，处理订单全生命周期"
```

## 填坑提醒

context 的"一句话定位"是**最高频被读**的字段：
- AI 第一次接触项目时会先看
- 出现在多个文档的顶部
- 会被其他 skill 引用

**必须具体，不能空话**：
- ✅ "处理圆通快递订单的全生命周期"（具体）
- ❌ "高效的订单处理平台"（空话）
