# 订单中心单元测试运行器
自动执行项目Maven单元测试命令，统计测试通过率，捕获编译错误、业务异常、断言失败等日志信息。

## 强制规范
- 遵循 always-on.md 全局规则
- 严禁修改已有业务代码、测试代码内容，仅做执行与日志收集
- 测试执行命令、日志输出格式、结果判定标准严格遵循项目测试运维规范
- 每执行完一条步骤必须输出执行状态，禁止静默后台运行
- 流程结束严格使用固定输出格式输出

### 任务拆解强制规则

1. 每个步骤必须作为独立待办任务，不得合并
2. 每个步骤必须独立完成后才能标记为完成

## 所需参数
| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| runModule | String | 是 | 需要执行测试的目标模块名 | lms-order-create-ms |
| testEnv | String | 否 | 测试运行环境，默认dev | dev、uat |
| fullScanTest | Boolean | 否 | 是否全量执行测试，默认仅执行新增测试类 | false |

## 输入向导

与步骤 2 合并执行：
- 工作流触发：跳过交互，直接读取流水线上下文参数
- 用户触发：参数缺失引导补齐

## 执行流程

### 步骤1：提取参数
- 自动提取上下文入参：runModule、testEnv、fullScanTest
- 参数任意缺失直接终止并提示缺失字段
- 输出：`runModule={runModule}, testEnv={testEnv}, fullScanTest={fullScanTest}`

### 步骤2：区分触发模式
- 全链路工作流触发：跳过交互问答，直接读取流水线上下文参数执行
- 用户手动触发：参数缺失引导补齐后再执行测试

### 步骤3：校验目标模块目录
- 进入目标业务模块目录，校验测试代码目录是否存在
- 检查路径：`{runModule}/src/test/java/`
- 输出：✅ 步骤3完成，测试目录 {存在/不存在}

### 步骤4：校验 Maven 环境
- 检查 `mvn` 命令是否可用
- 若 `mvn` 命令不存在 → 终止并提示用户配置 Maven 环境变量，禁止自行搜索路径
- 输出：✅ 步骤4完成，Maven 环境 {可用/不可用}

### 步骤5：执行单元测试
- 执行标准单元测试运行命令，阻塞等待执行完成
- 遇到以下环境问题时终止并提示用户处理，禁止自行绕过：
  - 依赖解析失败 → 终止并提示用户先执行 `mvn install`，禁止自行 install
  - 测试被 skip（surefire 配置 `<skip>true</skip>`）→ 终止并提示用户检查 pom.xml 中 surefire 配置，禁止自行修改 pom
- 输出：✅ 步骤5完成，测试执行 {成功/失败/编译失败}

### 步骤6：解析测试日志
- 自动解析控制台日志，区分：编译失败、用例断言失败、业务代码异常、测试通过四类结果
- 输出：✅ 步骤6完成，日志解析完成

### 步骤7：统计测试结果
- 统计成功用例数、失败用例数、异常堆栈信息，统一封装测试结果
- 输出：✅ 步骤7完成，测试结果统计完成

### 步骤8：执行检查清单
- 详见 [checklist.md](checklist.md)，如果有任何项未通过，提示用户需要修复，修复后继续执行检查，最多检查 3 次
- 输出：检查清单结果

### 步骤9：输出最终结果
- 按照 输出格式固定模板输出

## 检查清单

详见 [checklist.md](checklist.md)

## 输出格式
### 一、测试执行基础信息
| 字段 | 值 |
|------|-----|
| 执行模块 | {runModule} |
| 运行环境 | {testEnv} |
| 执行模式 | {全量测试/新增测试} |
| 整体测试结果 | {PASS / FAIL} |

### 二、测试执行统计结果
| 统计项 | 详情 |
|---------|---------|
| 总执行用例数 | {总数} |
| 成功用例数 | {成功数量} |
| 失败用例数 | {失败数量} |
| 异常信息 | {精简报错堆栈/无异常} |
