# 订单中心需求分析全流程流水线

## 强制规范
- 遵循 always-on.md 全局规则
- 所有代码/配置的生成必须通过指定的子 Skill 完成，流水线自身不得创建、修改任何文件
- 任何步骤失败，立即终止并输出错误信息

### 任务拆解强制规则（禁止合并阶段）

**在生成待办任务列表（Todo）时，必须严格遵循以下规则：**

1. **每个阶段必须作为独立的一条待办任务**，共 6 条，不得合并、不得省略
2. **每条待办必须包含完整的阶段名称和目标描述**，格式如下：
   - `阶段 1: 创建需求目录 — 初始化版本化需求目录`
   - `阶段 2: 生成需求规格说明书 — 调用 yto-generator-spec 生成 spec.md`
   - `阶段 3: 设计评审（clarify） — 调用 yto-design-analyzer 检查模糊点`
   - `阶段 4: 生成技术实现方案 — 调用 yto-generator-plan 生成 plan.md`
   - `阶段 5: 设计评审（analyze） — 调用 yto-design-analyzer 检查一致性问题`
   - `阶段 6: 流水线完成 — 输出执行状态表和产物清单`
3. **严禁出现以下合并写法**：
   - ❌ `阶段 2-5: 生成spec/plan并评审`
   - ❌ `后续阶段（阶段 4-6）`
4. **每个阶段必须独立完成后才能标记为完成**，前一个阶段未完成不得开始后一个阶段

---

## 所需参数
用户必须提供完整的业务需求描述。
示例：需求解析 我需要一个订单导出功能，支持按时间范围导出订单数据为Excel文件

## 执行流程

### 阶段 1：创建需求目录（自动执行）
创建目录：`.requirements/{需求名称}-{版本号}`,若存在则取最大版本号+1，版本号设为`1.0.0`

### 阶段 2：生成需求规格说明书（需确认）
1. 调用spec生成器，传入用户提供的业务需求/yto-generator-spec
   businessDemand: {{用户输入的完整业务需求描述}}
   outputPath: {{当前工作目录}}/spec.md
2. 输出生成的spec.md内容预览
3. 暂停执行，等待用户确认
   - 用户回复"确认"：进入阶段3
   - 用户回复"修改"：根据用户反馈重新生成spec.md
   - 用户回复"终止"：结束流水线

### 阶段 3：设计评审（clarify模式）
1. 调用设计分析器，对spec.md进行模糊点检查
   /yto-design-analyzer
   mode: clarify
   inputFile: {{当前工作目录}}/spec.md
2. 如果发现模糊点：
   - 输出所有需要澄清的问题列表
   - 暂停执行，等待用户回复解答
   - 用户解答后，更新spec.md并重新检查
3. 如果没有模糊点：
   - 输出：✅ 阶段3完成 | 设计无模糊点
   - 自动进入阶段4

### 阶段 4：生成技术实现方案（需确认）
1. 调用plan生成器，传入确认后的spec.md
   /yto-generator-plan
   specFile: {{当前工作目录}}/spec.md
   outputPath: {{当前工作目录}}/plan.md
2. 输出生成的plan.md内容预览
3. 暂停执行，等待用户确认
   - 用户回复"确认"：进入阶段5
   - 用户回复"修改"：根据用户反馈重新生成plan.md
   - 用户回复"终止"：结束流水线

### 阶段 5：设计评审（analyze模式）
1. 调用设计分析器，对plan.md进行问题分析
   /yto-design-analyzer
   mode: analyze
   inputFile: {{当前工作目录}}/plan.md
2. 如果发现严重问题：
   - 输出所有严重问题列表
   - 暂停执行，等待用户修复确认
   - 用户修复后，重新检查
3. 如果没有严重问题：
   - 输出：✅ 阶段5完成 | 设计通过评审

### 阶段 6：流水线完成
1. 生成最终的执行状态表
2. 输出所有产物文件的完整路径
3. 提示用户：plan.md 已包含所有必要信息，可直接进入执行阶段
4. 提示用户下一步操作：使用 yto-dev-execute-pipeline 执行代码生成

## 输出格式
### 阶段执行状态
| 阶段 | 状态 | 产物 |
|------|------|------|
| 1. 创建需求目录 | ✅ 完成 | .requirements/xxx-1.0.0/ |
| 2. 生成spec.md | ✅ 完成 | .requirements/xxx-1.0.0/spec.md |
| 3. 设计澄清 | ✅ 完成 | - |
| 4. 生成plan.md | ✅ 完成 | .requirements/xxx-1.0.0/plan.md |
| 5. 设计分析 | ✅ 完成 | - |

### 产物清单
- spec.md：需求规格说明书
- plan.md：技术实现方案（包含所有执行所需信息）

### 下一步操作
plan.md 已包含所有必要信息（模块清单、业务类清单、中间件配置、依赖关系、Plugin调度策略），
可直接使用 yto-dev-execute-pipeline 进行代码生成。
