# 生成后自检清单 (Checklist)

---

## 阶段 1：创建需求目录自检

- [ ] 需求目录命名是否符合 `.requirements/{需求名称}-{版本号}` 格式
- [ ] 版本号是否正确（首次为 `1.0.0`，已存在则取最大版本号+1）
- [ ] 目录是否成功创建

## 阶段 2：生成 spec.md 自检

- [ ] yto-generator-spec 是否成功调用
- [ ] spec.md 是否已生成到需求目录下
- [ ] spec.md 内容是否已展示给用户预览
- [ ] 是否已暂停等待用户确认（确认/修改/终止）
- [ ] 用户确认后 spec.md 是否已最终定稿

## 阶段 3：设计评审（clarify）自检

- [ ] yto-design-analyzer（clarify 模式）是否成功调用
- [ ] 模糊点是否已全部识别并列出
- [ ] 用户解答后 spec.md 是否已更新
- [ ] 无模糊点时是否输出了 ✅ 完成状态并自动进入下一阶段

## 阶段 4：生成 plan.md 自检

- [ ] yto-generator-plan 是否成功调用
- [ ] plan.md 是否已生成到需求目录下
- [ ] plan.md 内容是否已展示给用户预览
- [ ] 是否已暂停等待用户确认（确认/修改/终止）
- [ ] 用户确认后 plan.md 是否已最终定稿

## 阶段 5：设计评审（analyze）自检

- [ ] yto-design-analyzer（analyze 模式）是否成功调用
- [ ] CRITICAL 问题是否已全部识别
- [ ] 严重问题是否已提示用户修复
- [ ] 无严重问题时是否输出了 ✅ 通过状态

## 阶段 6：流水线完成自检

- [ ] 执行状态表是否完整（6个阶段全部列出）
- [ ] 产物文件路径是否全部列出（spec.md、plan.md）
- [ ] 是否提示用户使用 yto-dev-execute-pipeline 进入执行阶段

## 通用自检

- [ ] 各阶段是否严格按顺序执行，无跳过
- [ ] 每个阶段是否作为独立待办任务（未合并）
- [ ] 阻塞步骤是否等待用户确认后才继续
- [ ] 全程中文输出
