# 生成后自检清单 (Checklist)

---

## 步骤 1-3：信息收集自检

- [ ] businessDemand 是否已正确提取（文件路径或文本）
- [ ] 触发模式是否正确区分（工作流触发/用户触发）
- [ ] 参数缺失时是否直接终止并提示
- [ ] 业务地图 `.spec/oc-project-business-map.md` 是否已读取

## 步骤 4：spec.md 生成自检

- [ ] spec.md 是否包含上下文摘要（业务背景、目标用户、核心问题）
- [ ] 是否包含用户故事与验收标准（Given-When-Then 格式）
- [ ] 功能需求是否使用 FR-XXX 编号格式
- [ ] 是否严格区分功能需求与非功能需求
- [ ] 非功能需求是否仅在需求明确提及时才写（不自行推测）
- [ ] 是否包含业务实体与数据边界（自然语言描述，不定义表结构或类名）
- [ ] 是否包含范围外声明
- [ ] 是否未写入技术实现方案（类名、接口路径、框架、数据库）
- [ ] 是否未自行推导用户未提及的业务细节
- [ ] spec.md 是否已保存到当前需求目录下

## 步骤 5：用户确认自检

- [ ] 是否已暂停等待用户确认
- [ ] 用户回复"确认"后是否继续
- [ ] 用户提出修改后是否重新生成并再次等待确认

## 通用自检

- [ ] 全程中文输出
- [ ] 每个步骤是否作为独立待办任务（未合并）
