# 订单中心测试失败代码自愈修复器
依托单元测试报错日志，在不改动原有业务架构、不篡改规范命名的前提下，修复语法错误、参数错误、逻辑低级错误、断言匹配错误。

## 强制规范
- 遵循 always-on.md 全局规则
- 严禁重构业务逻辑、修改接口出入参定义、改动数据库映射关系
- 严格遵循原代码生成规范，修复后代码格式、包名、注解与原有规范保持一致
- 最大自动修复重试次数遵循全局配置max_retry_times，达到上限停止自愈并提示人工介入
- 仅修复可自动化解决问题，复杂业务逻辑错误直接终止并输出报错提示

### 任务拆解强制规则

1. 每个步骤必须作为独立待办任务，不得合并
2. 每个步骤必须独立完成后才能标记为完成

## 所需参数
| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| failModule | String | 是 | 测试失败所属业务模块 | lms-order-create-ms |
| failClassName | String | 是 | 报错对应的业务类/测试类全名 | OrderController |
| errorLog | String | 是 | 单元测试原始失败日志堆栈 | 空指针异常、参数不匹配、断言失败 |
| retryCount | Integer | 否 | 当前已修复重试次数 | 1、2、3 |

## 输入向导
### 第一轮：修复参数自动装载
- 从测试执行结果上下文自动读取所有失败相关参数，无需手动输入
- 工作流联动场景全程无交互，静默完成解析与修复
- 手动调试场景可手动传入报错日志与目标类名进行定向修复
- 自动判断重试次数，达到上限直接终止自愈流程

## 执行流程

### 步骤1：提取参数
- 自动装载测试失败全量上下文参数：failModule、failClassName、errorLog、retryCount
- 参数任意缺失直接终止并提示缺失字段
- 输出：`failModule={failModule}, failClassName={failClassName}, retryCount={retryCount}`

### 步骤2：区分触发模式
- 工作流联动触发：跳过交互，静默完成解析与修复
- 用户手动触发：可手动传入报错日志与目标类名进行定向修复

### 步骤3：检查重试次数
- 检查 retryCount 是否达到最大重试次数（默认3次）
- 若达到上限 → 终止自愈流程，输出人工介入提示
- 若未达到上限 → 进入步骤4
- 输出：{继续修复/已达上限终止}

### 步骤4：解析错误类型
- 解析 errorLog 区分错误类型：
  - 语法错误、导包缺失、注解缺失
  - 测试断言不匹配
  - 简单参数传参错误、空指针初始化缺失
  - 复杂业务逻辑异常
- 输出：✅ 步骤4完成，错误类型判定为 {语法错误/断言错误/运行时异常/复杂业务逻辑异常}

### 步骤5：判断是否可自动修复
- 根据步骤4判定的错误类型判断是否可自动修复：
  - 语法错误、导包缺失、注解缺失 → 可自动修复，进入步骤6
  - 测试断言不匹配 → 可自动修复，进入步骤6
  - 简单参数传参错误、空指针初始化缺失 → 可自动修复，进入步骤6
  - 复杂业务逻辑异常 → 不可自动修复，终止流程
- 输出：{可自动修复/不可自动修复需人工处理}

### 步骤6：读取目标类代码
- 读取测试失败的业务类代码：`{failModule}/src/main/java/{对应包路径}/{failClassName}.java`
- 读取对应的测试类代码：`{failModule}/src/test/java/{对应包路径}/{failClassName}Test.java`
- 输出：✅ 步骤6完成，已读取 {failClassName}.java 和 {failClassName}Test.java

### 步骤7：读取依赖类代码
- 读取错误日志中涉及的依赖类代码（仅允许扫描范围内列出的类）
- 输出：✅ 步骤7完成，已读取 {N} 个依赖类

### 步骤8：执行定向修复并回写文件
- 根据步骤4判定的错误类型执行定向修复：
  - 语法错误、导包缺失、注解缺失：直接补齐修正
  - 测试断言不匹配：同步调整测试类断言内容
  - 简单参数传参错误、空指针初始化缺失：补充默认初始化逻辑
- 保留原有方法结构、类名、包名、业务注解，仅修改错误片段
- 修复完成后回写文件
- 输出：✅ 步骤8完成，代码修复完成并已回写

### 步骤9：执行检查清单
- 详见 [checklist.md](checklist.md)，如果有任何项未通过，提示用户需要修复，修复后继续执行检查，最多检查 3 次
- 输出：检查清单结果

### 步骤10：输出最终结果
- 按照 输出格式固定模板输出
- 等待工作流重新触发单元测试执行流程

## 检查清单

详见 [checklist.md](checklist.md)

## 输出格式
### 一、代码修复基础信息
| 字段 | 值 |
|------|-----|
| 报错所属模块 | {failModule} |
| 异常关联类 | {failClassName} |
| 错误类型 | {语法错误/断言错误/运行时异常} |
| 当前重试次数 | {retryCount} |

### 二、代码修复结果
| 修复位置 | 修复详情 |
|---------|---------|
| 修复文件路径 | {完整Java文件路径} |
| 修复内容简述 | {补齐导包/修正断言/初始化参数/补全注解} |
| 修复状态 | {修复完成/无法自动修复需人工处理} |
