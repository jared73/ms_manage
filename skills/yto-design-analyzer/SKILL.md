# 设计质量分析器

## 强制规范
- 遵循 always-on.md 全局规则
- 可读取项目 .spec 目录下的所有文件，用于验证一致性
- 分析结果必须明确标记问题严重程度（CRITICAL / WARNING / MISSING）
- 对于 CRITICAL 问题，必须强制修正后才能继续流程
- 用户可跳过本步骤（回复“跳过”）

### 任务拆解强制规则

1. 每个步骤必须作为独立待办任务，不得合并
2. 每个步骤必须独立完成后才能标记为完成

## 所需参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| mode | String | 是 | `clarify` 或 `analyze` |
| specFilePath | String | 是 | spec.md 文件路径 |
| planFilePath | String | analyze 模式必填 | plan.md 文件路径 |

## 执行流程

### 步骤1：确定执行模式
- 根据 mode 决定执行路径：`clarify` → 进入步骤2；`analyze` → 进入步骤7
- 若 mode缺失 或 不是（clarify 或 analyze），直接终止并提示“mode 无效，仅支持 clarify 或 analyze”。

---

### clarify 模式

#### 步骤2：读取 spec.md
- 读取文件：{specFilePath}
- 输出：✅ 步骤2完成，已读取 spec.md

#### 步骤3：扫描模糊点
- 扫描是否存在以下问题：
    - 主观描述（如"快速"、"用户友好"）
    - 未量化的性能指标
    - 遗漏的异常流程
    - 未定义的数据边界
- 输出：发现 {N} 个模糊点

#### 步骤4：提出澄清问题
- 列出所有模糊点，但最多呈现 5 个高优先级问题，其余可汇总提示
- 每个问题附带推荐选项
- 输出：问题列表

#### 步骤5：阻塞等待用户答复
- **必须暂停执行，等待用户输入**
- 用户答复 → 进入步骤6
- 用户回复"跳过" → 跳过本 Skill，返回调用方

#### 步骤6：更新 spec.md
- 使用文件编辑工具直接修改 spec.md，并将修改后的内容摘要告知用户，修改前无需再次确认
- 输出：✅ 步骤6完成，spec.md 已更新

---

### analyze 模式

#### 步骤7：读取 spec.md
- 读取文件：{specFilePath}
- 输出：✅ 步骤7完成，已读取 spec.md

#### 步骤8：读取 plan.md
- 读取文件：{planFilePath}
- 输出：✅ 步骤8完成，已读取 plan.md

#### 步骤9：读取业务地图
- 读取文件：`.spec/oc-project-business-map.md`
- 输出：✅ 步骤9完成，已读取业务地图

#### 步骤10：检查 FR 覆盖性
- 检查 plan.md 是否覆盖了 spec.md 中的所有功能需求（FR）
- 输出：{已覆盖N项 / 未覆盖N项，未覆盖列表}

#### 步骤11：检查模块引用一致性
- 检查 plan.md 中的模块/中间件引用是否与业务地图冲突
- 输出：{一致 / 冲突N项，冲突列表}

#### 步骤12：检查跨产品线调用原则
- 检查是否违反了跨产品线调用必须通过 Client 的原则
- 输出：{合规 / 违规N项，违规列表}

#### 步骤13：检查类和模块定义完整性
- 检查 plan.md 中引用的类、模块是否在业务地图或设计方案中明确定义
- 输出：{完整 / 缺失N项，缺失列表}

#### 步骤14：输出审查报告
- 列出所有 CRITICAL / WARNING / MISSING 问题
- 输出：审查报告表格

#### 步骤15：处理 CRITICAL 问题
- 若存在 CRITICAL 问题：提示用户修正 plan.md，由用户决定是否让 AI 自动修正。未经用户明确同意，不得自动修改文件
- 若无 CRITICAL 问题：输出通过，自动进入下一步（若被主 Skill 调用）
- 输出：✅ 步骤15完成，analyze 模式结束

详见 [checklist.md](checklist.md)

## 输出格式
- clarify 模式：输出问题列表及用户答复后的更新摘要。
- analyze 模式：输出检查结果，格式如下：
  | 编号 | 严重程度 | 问题描述 | 涉及文件 | 修复建议 |
  |------|------|------|------|------|
  | 1 | CRITICAL | 问题描述1 | 文件1 | 修复建议1 |
  | 2 | WARNING | 问题描述2 | 文件2 | 修复建议2 |
  | 3 | MISSING | 问题描述3 | 文件3 | 修复建议3 |
